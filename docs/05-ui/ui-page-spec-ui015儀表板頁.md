# UI Page Spec v1

## UI-015 Dashboard 頁

> 依據：decision-log D-057 第 4 點（儀表板時間區間選填、依案件建立時間、含起不含迄）、D-042／D-047（院區範圍）、D-055 第 6 點的說明（統計摘要只有件數與比率，不含分數）、D-033（不保留前一身分的資料）；api-spec 15.1；頁面清冊 UI-015；資訊架構「查看統計、追蹤歷程、匯出報表」路徑。
> 預設區間、篩選條件與呈現方式依負責人 2026-11-17「照建議」的裁決：預設上一個整月且可清除為不限期間、提供選填的專案條件、只用數字呈現（不加圖表）。

---

## 1. 頁面基本資訊

### Page ID
`UI-015`

### 頁面名稱
Dashboard 頁

### 頁面目的
依條件查看審查狀況的摘要：總案件數、已結案、有複審、逾期，以及完成率、複審率、逾期率。

### 頁面型態
`Summary`

### 對應 IA 模組
`查詢與報表`

### 對應主要角色
- `HOSPITAL_MANAGER`
- `AUDITOR`
- `SYSTEM_ADMIN`（只有彙總數字，本來就不含分數）

### 不開放角色
- `REVIEWER`
- `REREVIEWER`

### 對應主要 API
- `GET /reports/dashboard-summary`（api-spec 15.1）

### Route 與模組
- Route：`/reports/dashboard`（資訊架構建議路徑）
- Feature module：`features/reports`（與 UI-017 同模組，lazy-loaded）
- 角色 guard：只允許上列三個角色，做法與 UI-017 相同。

---

## 2. 頁面責任範圍

本頁負責：
- 輸入日期區間、專案，以及 `SYSTEM_ADMIN` 才有的院區條件
- 呼叫 `GET /reports/dashboard-summary`，呈現件數與比率
- 提供前往案件列表頁、報表匯出頁的連結

本頁不負責：
- 計算任何統計數字：件數與比率完全以 API 回應為準，前端不自行重算
- 院區範圍的授權：由後端依 D-042／D-047 決定，前端只呈現 scope 摘要
- 逐案資料與下載：屬 UI-017

---

## 3. 頁面主要區塊

### 3.1 條件區

| 欄位 | 說明 |
|---|---|
| 日期區間 | 起日、迄日兩個日期欄位，**選填**；畫面上的迄日含當天，送出轉換與 UI-017 §4 相同。兩個都留空表示「不限期間」，不送 `from`、`to`。 |
| 專案 | 選填的文字欄位，輸入專案代碼；留空表示全部專案。有值時送 `projectId`（去掉前後空白）。 |
| 院區 | 只有持有 `SYSTEM_ADMIN` 的帳號顯示（含多角色帳號，判斷方式同後端 `readScopeHospitalId`），可留空表示全部院區。其他角色不顯示，scope 摘要寫明「本院」。 |

- 預設區間：上一個整月（與 UI-017 相同）。例如今天是 2026-11-17，起日 2026-10-01、迄日 2026-10-31。
- 「不限期間」按鈕：一次清空起迄日。
- 只填其中一個日期，或起日晚於迄日時，停用查詢按鈕並在欄位旁提示（後端對這兩種情況回 400，前端先擋）。
- **進入頁面即以預設條件查詢一次**；之後按「查詢」才重新查詢。

### 3.2 Scope 摘要

顯示目前查詢的條件：日期區間（含迄日當天，或「不限期間」）、專案（專案代碼或「全部專案」）、院區範圍（`SYSTEM_ADMIN` 為所選院區或「全部院區」，其他角色為「本院」）。

### 3.3 統計數字

以數字卡片呈現，不使用圖表：

| 卡片 | 來源 | 說明（顯示在卡片上） |
|---|---|---|
| 總案件數 | `totalCases` | 條件內的案件數，不含已取消的案件（D-087 第 4 點）；有日期區間時，只計入建立時間在區間內的案件 |
| 已結案 | `closedCases` | 狀態為已結案 |
| 有複審 | `rereviewedCases` | 已指派複審醫師（不代表複審已完成）；不含已取消的案件 |
| 逾期 | `overdueCases` | **查詢當下**已超過期限、且尚未結案或取消；不是區間內的歷史逾期數 |
| 完成率 | `completionRate` | 已結案 ÷ 總案件數 |
| 複審率 | `rereviewRate` | 有複審 ÷ 總案件數 |
| 逾期率 | `overdueRate` | 逾期 ÷ 總案件數 |

- 比率是 0～1 的小數，以百分比顯示到小數一位（例如 `0.8` 顯示 `80.0%`），並在旁邊顯示分子／分母（例如 `200 / 250`）。
- 前端不自行計算比率；分子分母取自同一個回應，對應同一個母體（PR #67 單一查詢）。

### 3.4 連結

- 「查看案件列表」→ `/cases`（UI-009）
- 「匯出報表」→ `/reports/export`（UI-017）
- 連結只導頁，**不帶入**本頁的條件；帶入條件需要目標頁支援讀取 query params，不在本頁範圍。

---

## 4. 日期區間的轉換

- 與 UI-017 §4 相同：日期是 `Asia/Taipei` 的日曆日期；`from` ＝ 起日 00:00 `+08:00`，`to` ＝ 迄日的**次日** 00:00 `+08:00`，以 UTC 時間點送出（D-077）。
- 「不限期間」時兩個參數都不送。

---

## 5. 頁面狀態

| 狀態 | 呈現 |
|---|---|
| 載入中 | 條件區與按鈕停用，數字區顯示載入狀態。進入頁面時即為此狀態。 |
| 有資料 | 顯示 scope 摘要與數字卡片。 |
| 無資料 | `totalCases = 0`：以插圖型空狀態顯示「此條件沒有案件」，scope 摘要照常顯示。 |
| 請求錯誤 | `400`：顯示後端回傳的訊息。其他錯誤：顯示「查詢失敗，請稍後再試」，保留條件。 |
| 無權限 | `403`：顯示「無權限」區塊，不顯示數字（與 UI-017 相同）。 |

---

## 6. 權限與可見性

- `HOSPITAL_MANAGER`、`AUDITOR`：只看本院（D-042）；不顯示院區欄位。
- `SYSTEM_ADMIN`：可選院區或全部院區（D-047）；本頁只有彙總件數與比率，不含任何分數。
- 身分、院區或角色改變時，取消進行中的查詢、清除畫面上的數字，再以目前條件重新查詢（D-033，做法同 UI-017）。

## 7. 版面

依 `.ai/governance/frontend-ui.instructions.md` 與 `frontend-design-language-mfe.md`，與 UI-017 相同：
- 根結構 `system-container[container-type=main]`；條件與主要操作放 `system-block[header]`（sticky），scope 摘要、數字卡片與連結放 `system-block[main]`。
- 空狀態使用插圖型（`Empty.svg`）。
- 元件 CSS 不得硬寫色碼。

---

## 8. 頁面測試重點

1. 進入頁面即以台北的上一個整月查詢一次；送出的 `to` 為迄日次日 00:00 `+08:00` 的 UTC 時間點。瀏覽器不在 UTC+8 時結果相同。
2. 按「不限期間」後查詢，不送 `from`、`to`；scope 摘要顯示「不限期間」。
3. 只填一個日期、或起日晚於迄日時，查詢停用。
4. 專案有值時送 `projectId`，留空不送。
5. 數字與比率依 API 回應呈現，比率顯示為百分比並附分子／分母；前端不重算。
6. `totalCases = 0` 顯示插圖型空狀態。
7. 持有 `SYSTEM_ADMIN` 才顯示院區欄位（含多角色帳號）；其他角色的 scope 摘要為「本院」。
8. 400 顯示後端訊息、其他錯誤顯示通用訊息、403 顯示無權限。
9. 身分改變時取消進行中的查詢並以新身分重新查詢。
10. `REVIEWER`、`REREVIEWER` 無法進入本頁。

---

## 9. 不屬於本頁處理的事項

- **評分分布**：頁面清冊列為主要內容，但 `GET /reports/dashboard-summary` 沒有提供分數相關欄位，且 D-055 的說明是統計摘要只有件數與比率、不含分數。若要加入，需先另行裁決後端契約與遮罩規則。
- 圖表：本版只用數字呈現。
- 依建立時間以外的時間欄位篩選（D-057 第 1 點只定義建立時間）。
- 歷史逾期數（區間內曾經逾期的案件）：後端目前只提供查詢當下的逾期數。
- 連結帶入條件到案件列表頁或報表匯出頁。
- 專案下拉選單：本版用文字輸入專案代碼。
- 報表匯出（UI-017）、稽核查詢（UI-016）。
