# 漏網紀錄

依 `04-definition-of-enough.md` 第二節：每一個漏網的缺陷都要回應，回應方式是下列之一：

- 新增或修復偵測器。
- 修訂律法。
- 由負責人裁決「這類缺陷放在清單之外」，並指明改由什麼涵蓋。

「漏網」指閘門全部通過，缺陷卻是靠人工核對、審查或使用者才發現的。

## 2026-11-27

兩筆都是 2026-11-27 的人工比對發現的：把前端 service 宣告的回應型別對照 `specs/*/http.yaml`（`docs/review/frontend-http-contract-reconciliation-2026-11-27.md`）。**兩筆都是讀程式得到的，沒有拿前端去打真實的後端。** 發現時四項必要檢查（`check`、`law-check`、`law-selftest`、`frontend-check`）都是綠的。

程式寫於何時沒有查（本機是淺層複製，看不到那麼早的歷史）。

同一次比對另外看到三件，**不算漏網**，記在這裡備查：

- 提交明細的 `masked`、`whitelist` 形狀裡 `answers` 是 null 或不存在，前端直接 `.map`。目前沒有頁面會拿到這兩種形狀，走不到。
- 後端仍在輸出 D-032 已撤銷的 `rereviewContext.closedRevisionException`。前端不讀。
- `SamplingBatchFailedEvent` 用拼字串把自由文字帶進稽核的 JSON（D-098 的草稿查到的）。目前沒有任何行為會產生失敗的批次，走不到。
